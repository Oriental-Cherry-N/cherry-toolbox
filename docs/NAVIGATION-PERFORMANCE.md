# 页面切换延迟修复

2026-09-11：针对“切换左侧页面或返回主页时，点击后几秒才响应”。

## 原因与测量

离开网卡页面会调用完整恢复流程。即使没有修改网卡、没有待恢复记录，该流程也会进行四次网卡枚举与三次 ChatGPT 进程查询。每次查询单独启动 Windows PowerShell；导航等待所有操作完成后才切换，而且原先没有等待提示。

在本机调用同一份编译后的主进程退出函数，使用空的临时恢复目录和实际 Windows 只读查询，得到以下单次对比：

| 未修改网卡时离开页面 | 修复前 | 修复后 |
| --- | ---: | ---: |
| PowerShell 查询次数 | 7 | 0 |
| 主进程退出逻辑耗时 | 6,912 ms | 2 ms |

这不是所有界面操作的延迟保证，也不包含 IPC 与页面绘制时间。原始结果见 `.tmp/navigation-before.json` 和 `.tmp/navigation-after.json`，测量脚本为 `.tmp/benchmark-navigation.cjs`。

## 改动

- 没有网卡恢复任务、独立恢复程序没有执行恢复、没有恢复错误且日志健康时，直接恢复页面选择并使用已有网卡列表，不再扫描系统网络。
- 离开隔离浏览器页面仍等待会话清理；清理结束后直接返回更新后的组件状态。只有旧版全局网络恢复需要再次扫描网卡。
- 等待超过 150 ms 时显示“正在停止并恢复当前工具，完成后切换页面…”。清理失败仍保留当前页面，允许重试。
- 真实网卡恢复后的核验、损坏日志拒绝、退出强制清理与 ChatGPT 保护保留。

## 验证

- 主进程和渲染进程 TypeScript 类型检查通过。
- `node --test test/*.test.js`：**94/94 通过**，包含五项新增回归，覆盖无改动退出、等待真实恢复确认、损坏日志保留、隔离浏览器退出与旧全局恢复。
- 临时浏览器运行实际渲染模块，确认等待提示可见、清理完成后切页、清理失败留在原页、重试成功，渲染异常为零。
- 测试中的模拟失败代理现在处理浏览器主动重置的连接，避免测试进程因预期的 `ECONNRESET` 意外退出；生产代理逻辑未在本次更改。

测试不会启停真实网卡、修改系统网络或操作真实 ChatGPT/微信账号。日志为 `.tmp/navigation-tests.log`、`.tmp/navigation-ui-check.json`；等待提示截图为 `.tmp/navigation-progress-ui.png`。
