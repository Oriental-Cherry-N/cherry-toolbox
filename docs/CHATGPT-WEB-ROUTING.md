# ChatGPT 网页分流

实施日期：2026-09-09。入口为 **浏览器分流 → 浏览器模式 → ChatGPT 网页**。

本次改进只接管工具箱专门打开的临时 Edge/Chrome。ChatGPT 桌面端、Codex、普通浏览器继续使用原有网络设置。新模式把整个临时浏览器放在同一条代理路径上，登录重定向、静态资源、文件请求和后续新增域名都遵循相同规则，避免按域名遗漏依赖。

## 使用

1. 自行连接有线和 WLAN，在 FlClash 的 GLOBAL 中选定受支持的具体 TCP 节点；控制接口与 mixed proxy 必须只监听回环地址。
2. 进入“浏览器分流”，选择“ChatGPT 网页”、有线网卡和 WLAN 网卡，按需输入控制端口与密钥。域名列表在此模式中不可编辑。
3. 运行预检，再点击“打开隔离浏览器”。在新窗口中登录 ChatGPT。
4. ChatGPT 页面加载后点击“验证流量路径”。若验证失败，组件会停止会话并清理临时资源；浏览器中的登录和下载也会被清理。
5. 完成使用后点击“关闭并清理会话”。关闭临时窗口、离开组件或退出工具箱也会触发清理。

登录状态不跨会话保留。浏览器的自动下载被指定到该会话的 `Downloads` 子目录，退出时随配置目录删除。上传仅读取用户明确选择的源文件，清理不会删除该源文件。首次版本禁用麦克风、摄像头和非代理 WebRTC UDP，因此不把语音功能列为支持项。

## 实现与保护

| 项目 | 当前行为 |
| --- | --- |
| 流量路径 | 临时浏览器 → 固定回环代理 → 专用 Mihomo → 所选 WLAN/节点。整个网页会话使用代理，没有 DIRECT 后备。 |
| 固定出口 | 节点在启动时复制到会话配置，运行中不跟随共享 FlClash 自动切换；网卡断开、身份变化、绑定失败或守护进程失联会停止会话。 |
| 系统范围 | 不修改系统代理、环境变量、DNS、路由、网卡指标或共享 FlClash，不启用 TUN，不请求 UAC。 |
| 长连接 | 15 秒超时只用于初始握手；进入双向转发前将收发超时清零并开启 TCP keepalive。ChatGPT 模式保留 HTTP/2；原“指定网站”模式继续禁用 HTTP/2，维持域名隔离。 |
| 浏览器控制 | CDP 使用父子进程继承的匿名管道，不监听本机调试 TCP 端口，不生成 `DevToolsActivePort`。控制通道断开时关闭受管浏览器。 |
| 配置隔离 | 新建一次性 profile，不加载普通浏览器的扩展、登录或同步资料；阻止覆盖代理、下载目录、扩展及自动唤起外部应用的企业策略。 |
| 外部应用 | 一次性 profile 不带外部协议的自动放行规则；自动放行策略存在时拒绝启动。用户主动确认外部协议提示后的操作不属于本组件能撤销的范围。 |
| 临时资源 | 浏览器、专用内核均在执行前加入 Windows Job，退出终止进程树；随后删除 profile、下载和临时内核目录。清理失败保留记录并阻止新会话，支持重试与下次启动恢复。 |
| 模式互斥 | 与“指定网站”共享同一生命周期，无法同时开启或运行中切换；退出恢复进入组件前载入的设置，既有设置文件不被覆盖。 |
| 旧版恢复 | 旧 `chatgptEnabled` 开关仍强制关闭。v3/v4 恢复信封先校验磁盘中的原始内容，再补充模式默认值，避免升级后误判旧日志损坏。 |

当前支持 IPv4、80/443 端口的 HTTP/HTTPS 网站及受支持的 TCP 节点。HTTPS CONNECT 透传加密字节，不安装证书或解密聊天内容；HTTP 流式响应和 WSS 按 TCP 隧道转发。QUIC 不启用。浏览器自身的后台请求若产生，也使用同一固定代理；这种模式不是只允许访问 ChatGPT 的网站白名单。

## 路径验证的含义

“ChatGPT 网页”验证组合以下证据：

- 临时浏览器中确有 `https://chatgpt.com` 的安全文档，且已进入可交互或完成状态；只读取 origin、readyState、isSecureContext，不读取聊天正文、输入或 Cookie。
- 本会话网关记录过 `chatgpt.com` 的代理连接，且没有主网卡直连记录。
- 浏览器通过代理取得 `ipinfo.io` 的实时出口响应。
- 专用内核 PID 的非回环活动 TCP 连接全部使用所选 WLAN 的本地地址。
- 启动前后的全局网络指纹一致，受管进程仍在运行。

网页模式不探测普通客户端的出口，也不以“两次公网 IP 不同”作为唯一证据。ChatGPT 安全页面可能仍是登录页或服务方的验证页，因此“路径通过”不能解释成聊天、登录或上传功能全部通过。
