## 已实现

| 问题 | 当前处理 |
| --- | --- |
| 备份落后于最新恢复状态 | v4 三份相同的最新状态；先落盘复核再变更；持久完成标记防止旧备份复活 |
| 一个清理失败阻止其他组件 | 统一入口逐项尝试并汇总错误；停止期间拒绝新工作；失败保留状态并允许重试 |
| 第一张网卡缺失阻止其他网卡恢复 | 管理员程序逐张尝试，持续重试缺失或失败的网卡 |
| 用户可写脚本被提权执行 | 新网卡事务使用固定 C# 程序和结构化管道；旧恢复只允许有长度上限的内存命令，不生成待执行脚本文件 |
| 程序崩溃后浏览器或 worker 残留 | 子进程以挂起状态创建，加入无逃逸权限的 Windows Job 后运行；心跳和管道断开提供独立退出兜底 |
| 停止超时后丢失进程引用 | 只有核实进程退出与资源清理后才清除引用，失败可再次停止 |
| PAC 下载失败可能直连 | 改用固定本机代理；无 DIRECT 后备；禁用 QUIC、非代理 WebRTC UDP 和后台网络活动 |
| 网卡下拉选择不控制出口 | 普通连接用源地址与 IP_UNICAST_IF 双重绑定；专用 Mihomo 内核和 DNS 绑定所选 WLAN |
| 自定义父域覆盖 OpenAI | 保护名单优先，拒绝匹配保护域、子域或祖先后缀的自定义规则 |
| Node 探针不能证明浏览器分流 | 浏览器自身打开临时验证页，结合网关记录和专用内核的实际套接字地址判定 |
| 微信检测会改变窗口状态 | 只绑定用户已打开的私聊窗口，移除开窗、焦点、最小化操作；仍无发送分支 |
| 运行期间改写设置 | 设置仅在组件会话中生效，离开后恢复原始设置，既有配置文件不改写 |
| 安全中心固定显示成功 | 使用实际日志健康度、检查结果和组件待恢复状态显示；微信进程清理失败计入待办，并阻止新变更 |
| 用户恢复日志损坏提前阻断其他清理 | 仍尝试浏览器、微信 worker 和管理员独立恢复记录；汇总未完成项目，保留损坏证据 |

## 验证方式

`npm run verify` 包括类型检查、原有测试和新增故障回归。新增用例执行真实 Windows Job 的子进程退出与临时目录删除、管道断开与守护进程被终止后的兜底、清理失败重试、最新恢复镜像与完成标记，以及域名保护优先级。无界面浏览器测试只使用本机代理与目标端口，验证代理故障后不会绕过代理连接目标。

`mihomo -t` 验证生成配置是否被固定版本内核接受，使用虚构节点，无外部连接。打包检查验证本机辅助程序与内核位于可执行的 asar 解包目录中，校验数据位于应用代码内。

## 依赖处理

- `fast-uri` 固定到 `3.1.6`，`@xmldom/xmldom` 固定到 `0.9.12`。
- 本次核查时，`extract-zip` 的 CVE-2026-56876 尚无上游修复版本。安装后和每次构建前应用明确的本地补丁：拒绝 ZIP 符号链接，并以排他方式创建文件，拒绝覆盖已有文件。恶意链接、覆盖已有文件与正常解压三类回归通过。`npm audit` 仍按上游版本报告该依赖链；不能把补丁描述为官方修复或全量审计零漏洞。
- 内核来源为官方 `MetaCubeX/mihomo` 的固定版本，档案摘要记录在安装脚本和 `native/core-manifest.json` 中。构建辅助程序哈希随应用一起生成；这用于发现组件错配，并不等于代码签名或抵御已控制整个用户账户的攻击者。

## 实机验收与范围

当前运行范围是临时浏览器中的 IPv4 HTTP/HTTPS 与 TCP 代理节点，不包括整机透明分流、IPv6、QUIC 或 UDP 节点。DNS 服务器需要支持 TCP 查询。不支持的模式明确拒绝，不静默换网卡。

以下需在隔离双网卡 Windows 环境完成，不能由单元测试代替：

1. UAC 允许、拒绝、超时，以及更换用户凭据时的身份验证。
2. 实际启停网卡后离开组件，确认管理状态与原状态逐一相同。
3. 多张网卡有待恢复时移除其中一张，确认其余网卡仍恢复，缺失项保留待办。
4. 浏览器分别访问普通网站、目标域名、OpenAI 保护域和重定向页面；观察所选网卡与公网出口。
5. 断开任一出口、停止内核或杀死主程序/守护程序，确认无跨网卡后备，资源被回收或留有可重试记录。
6. 锁屏、休眠、关机与重启，核查异常退出恢复；断电后只能在重新运行恢复程序时执行恢复。
7. 微信已打开窗口的焦点、显示状态和内容在启动/停止检测前后保持一致。

网络会话、浏览器主动发出的远端请求、用户主动操作和其他软件产生的变更不能被“恢复网卡状态”撤销。必要恢复证据与完成标记会保留；其他组件创建的临时进程、代理配置和浏览器资料应被清除。恢复失败必须显示为未完成。
