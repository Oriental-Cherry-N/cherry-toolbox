# 辅助程序版本隔离与退出修复

旧启动器在检查应用单实例之前，直接覆盖 `native/bin/CherryToolbox.Helper.exe` 并重新生成清单。已运行的主进程仍持有原清单的 SHA-256，因此后续网卡变更、恢复和退出都可能因校验失败而阻塞。单独运行旧 `typecheck` 命令也会覆盖辅助程序，但不会同步生成主进程 JavaScript。

## 改动

- 原生辅助程序改为 `native/bin/helpers/<SHA-256>/CherryToolbox.Helper.exe`。每次编译先使用源文件快照，在独立临时目录完成后发布新版本。旧版本和旧固定路径不会被覆盖。
- 构建输入包含源文件内容、编译器和编译选项。未变化时复用已通过哈希校验的文件；类型检查不生成应用 JavaScript，也不会破坏旧实例对应的辅助程序。
- 运行实例从自己的已编译模块固定路径和预期哈希。启动、恢复、状态检查和浏览器辅助进程都继续校验这一版本，不读取磁盘上新清单来改变信任依据。
- 源码启动器在构建之前用独立 Electron 入口请求单实例锁，已运行时只唤醒窗口。构建互斥锁将同时启动和构建串行化，新实例取得应用锁后才释放构建锁。后台启动的检测不会显示托盘窗口。
- 网卡变更在写入恢复意图前完成辅助程序校验，真正发送命令之前仍先保存恢复记录。未向 broker 提交的请求仅撤销本次意图，保留更早的恢复记录。
- 若本次未启动辅助程序、未发送命令，且启动时已确认没有独立恢复任务，校验失败后的清理无需再次执行损坏的文件。若启动恢复检查失败、已有启动标记或命令已发出，则仍须核实独立恢复状态，不能仅凭网卡看起来正常就解除退出保护。
- 完整性失败提供中文提示和可选中复制的诊断文本，包括进程、模块、固定辅助程序路径以及预期/实际 SHA-256。
- Windows 打包只携带当前应用需要的辅助程序版本，并再次核对打包模块和辅助程序哈希。

## 使用

双击桌面快捷方式的行为：未运行时编译并启动；已运行时显示已有窗口。修改源码后需要先正常退出旧实例，再次启动才会加载新应用代码。诊断入口仍为 `start-source.cmd`，主进程日志路径会显示在命令窗口。

不要手动删除正在使用的版本目录或通过删除恢复记录跳过实际恢复。正常构建不会清除历史辅助程序，旧实例可以继续恢复。

## 验证范围

回归测试包括真实编译、独立类型检查、并发构建、同时双击启动、运行期间再次构建、文件缺失和篡改、未发出命令后的退出、已有恢复记录的保留，以及先前的 Windows 管道认证和独立恢复测试。Electron 启动测试使用临时应用身份和配置目录，不启动用户的网卡组件。

本次完整验证通过 122 项测试，中文诊断界面验证和 Windows x64 打包也通过。源码、打包模块及辅助程序哈希一致。用户遗留的一条恢复意图已备份，在确认网卡启用状态符合原始记录、独立恢复存储为空后，通过生产退出流程完成对账；期间未写入真实网卡状态。

Electron 启动回归必须在正常 Windows 用户环境运行。受限 CodexSandbox 账户无法启动该环境的 Chromium 图形子进程，本次曾因此触发 Windows `0x80000003` 弹窗。测试现在会在该账户下直接报错，避免启动图形进程；不通过关闭产品安全设置来绕过。

自动测试不执行真实网卡启停，不请求管理员网卡授权，也不修改系统代理、路由或 DNS。真实管理员授权和网卡切换仍属于实机验收范围。
