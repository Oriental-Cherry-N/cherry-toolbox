# 网卡握手与退出修复（2026-09-11）

本次修复针对禁用网卡时出现 `The adapter broker handshake timed out.`，以及失败后无法退出的问题。继续保留独立管理员恢复、原始状态日志、ChatGPT 客户端保护和最后连接网卡保护。

## 故障原因

1. 原生程序在调用 `EndWaitForConnection` 前释放了异步等待句柄。真实 Windows 管道测试复现了“已关闭 Safe handle”。现在连接等待和结果读取共用同一段实现，读取结果后才释放句柄。
2. 服务端在读取客户端消息前调用 `RunAsClient`，违反 Windows 命名管道身份模拟的调用顺序。现在先读取有长度和时间限制的 `hello`，校验进程和账户，再发送 `ready`。身份验证完成时重新设置心跳起点。
3. 客户端只在存在待处理命令时处理断线，导致握手断线仍等待十秒，超时后还保留半连接。现在认证失败、断线、超时、写入失败都会清理连接及其等待任务；未经认证的连接不能执行网卡命令。
4. 用户会话标记与实际恢复状态脱节，退出流程又无条件抛出旧通信错误。现在使用独立恢复进程的互斥锁和管理员记录确认是否仍有工作，再核验实际网卡状态，最后清除日志及错误。

## 恢复与退出行为

- 启动失败且未发送操作：保留标记到核验完成，确认独立恢复空闲且无记录后清除。不会因为空标记再次请求管理员权限。
- 操作已发送但回执丢失：关闭连接让独立进程恢复，保留所有恢复证据，直到确认其已结束且记录为空。
- 首选恢复通信失败：继续尝试原有单次恢复路径。只有独立恢复状态及实际网卡状态均已核验，才能清除错误并退出。
- 独立恢复仍在执行、记录损坏或状态未知：保留原始状态，显示具体原因。不会把一次状态读取当成仍在执行的操作已经结束。
- 原生恢复仅在空记录持久化成功后清除内存中的原始状态；持久化失败继续重试。
- 界面显示授权、连接、认证、操作和恢复阶段。尚未发送操作时可取消启动；退出应用也会取消这部分等待。已经发出的操作须完成恢复核验。

## 验证

- `npm run verify`：115/115 通过，包含 21 项新增回归测试。
- 真实 Windows 命名管道：生产连接等待及身份认证方法可以与 Node 客户端完成握手；错误 PID、错误账户仍被拒绝，心跳起点正确重置。
- 失败注入：覆盖提前断线、无响应超时、协议不匹配、授权取消、恢复标记残留、管理员记录恢复、操作回执丢失和恢复回执丢失。
- 主进程：覆盖核验后退出、恢复未完成时保留原始记录、单次恢复成功后的清理，以及未执行意图的撤销。
- 独立浏览器界面测试：覆盖等待文案、取消启动、取消后返回主页、日志为空时重试恢复和恢复期间隐藏取消按钮。

测试使用临时目录、模拟网卡和受管测试浏览器。真实管道测试运行生产认证代码，但不提权、不启用或禁用网卡。真实 UAC 交互及物理网卡切换仍需要受控验收；不能将上述测试等同于这些操作已经实测。

本机此次故障留下的空会话标记已在真实用户账户下核验并清除：管理员恢复状态为空且空闲，用户三份恢复日志保持原样。没有更改网卡启用状态。
